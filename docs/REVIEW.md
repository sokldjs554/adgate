# 독립 코드 리뷰와 처리 현황

별도 에이전트(다른 컨텍스트, 설계 의도를 모름)가 저장소를 **읽기 전용**으로 훑고 결함을 *실행해서 재현*해 보고했다. 제한한 것: `data/test.jsonl`·`redteam*`·라벨러 파일을 읽지 않는다,
`eval --measure`·`gate` 를 실데이터로 돌리지 않는다, 네트워크·LLM 호출을 하지 않는다. 결과는 **심각 3 · 높음 8 · 중간 9 · 낮음 6 (26건)**. 리뷰어는 80개 사례 행렬을 만들었다(리뷰어가 본 HEAD 에서 68개 재현).
나는 그중 72개를 옮겨 고치기 전 코드에서 직접 실행했고 **57개가 재현**됐다(나머지 15개는 고친 규칙이 정상 소재를 건드리지 않는지 보는 음성 대조다). 72개 모두 회귀 테스트
(`tests/test_review_regressions.py`)로 고정했다. 정규식 성능 결함(C1·C2)은 별도로 직접 재현했다(숫자 22자리 2.1초, 4,000자 숫자열은 5분을 넘겨 중단).

이 리뷰는 같은 모델 계열의 다른 인스턴스가 했다는 한계가 있다. 그래도 설계자가 보지 못한 결함 26건을 찾았고, 그중 하나(C1)는 **직전에 내가 한 수정이 만든 회귀**였다 — [FAILURES.md F-17](FAILURES.md).

처리 표기: **고침** = 코드와 테스트 · **일부** = 부류를 막았지만 남은 위험이 있다 · **문서화** = 코드는 그대로 두고 문서를 정직하게 고쳤다 · **미해결** = 하지 않았고 이유가 있다.

## 리뷰어가 *문제없다*고 확인한 것

권한 검사(남의 건은 404, 존재 오라클 없음, 직무 분리), `resume` 원자성과 멱등성 경쟁(동시 6건 → 1건), 콘솔 XSS·CSP(`innerHTML` 없음, 코드포인트 오프셋 일치),
평소 입력에서의 구간 부기, 무작위 4,000건 퍼징(예외 없음, 모든 `verified` 수정안이 재심사에서 APPROVE), 도전자가 판정을 더 보수적으로만 만드는 성질, 지표 정의와 Wilson/κ 식,
Judge 설계(판정 필드 없음, 심각도는 정책, 인용 근거 필수, 실패는 REVIEW, 기존 발견을 지우지 못함).

## 이 리뷰가 보여 준 것

- 설계자가 *의도적으로 시험한* 곳(정규화·부정문)은 단단했고, **의도하지 않은 곳**(정규식의 증가율, 예외의 *범위*, 문서가 말한 것과 코드가 하는 것의 차이)에서 결함이 나왔다.
- 가장 위험했던 것은 가장 최근의 수정이었다. 수정 뒤에는 *수정에 대한* 검토가 필요하다.
- 리뷰의 가치는 개수가 아니라 재현 사례를 회귀 테스트로 남긴 데 있다. 72개 사례, 우회 행렬 256개, 증가율 46개가 지금 CI 에서 돈다.
