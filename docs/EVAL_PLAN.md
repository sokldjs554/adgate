# 평가 계획 (사전등록)

> 작성일 2026-10-11. **탐지기 코드를 쓰기 전에** 쓰고 커밋한다. 이 문서의 합격 기준은 측정 이후에 바꾸지 않는다.
> 바꿔야 한다면 바꾼 이유와 시점을 아래 [변경 기록](#변경-기록)에 남기고, 바꾸기 전 기준으로 판정한 결과도 함께 적는다.

## 1. 질문

"이 광고 심사 시스템이 좋다는 걸 어떻게 아는가?"를 먼저 묻는다. 좋다는 말을 서로 다른 실패에 대응하는 신호로 쪼갠다.

| 신호 | 막으려는 실패 | 지표 |
|---|---|---|
| 안전 | 위반 소재가 승인된다 | `hard_pass_through`, `unsafe_approve` |
| 공정 | 정상 소재가 반려·보류된다(부정문, 범위 표현, 면책 고지 같은 *정상 유사* 소재) | `false_reject`, `over_review` |
| 설명 | 반려 사유가 틀리거나 원문에 없다 | `rule_f1`, `localization`, `grounding` |
| 운영 | 사람이 모든 건을 봐야 한다 | `auto_rate`, `auto_precision` |
| 견고 | 광고주가 띄어쓰기·기호로 우회하거나, 소재 안에 명령을 심는다 | 우회·주입 슬라이스의 `unsafe_approve` |

## 2. 데이터

| 이름 | 작성자 | 규모(목표) | 용도 | 규칙 |
|---|---|---|---|---|
| `dev` | 설계자(손작성 + 변형) | ~70 | 반복 개선 | 자유롭게 본다 |
| `test` | 설계자(손작성) | ~70 | 최종 측정 | **탐지기 구현 전에 동결**. 코드 동결 후에만 측정. 측정할 때마다 [MEASUREMENTS.md](MEASUREMENTS.md)에 기록 |
| `redteam` | 정책 문서만 본 **독립 에이전트** | ~70 | 처음 만나는 입력에서의 성능 | 탐지기·저장소 코드를 보지 못한 상태에서 작성. 첫 측정(수정 전) 수치를 그대로 보존 |
| `generated` | 시드 생성기 | 600 | 대조군 | 생성기와 탐지기가 같은 가정을 공유하므로 **낙관적**이다. 헤드라인 수치로 쓰지 않는다 |

- 모든 소재는 합성이다. 실제 업체·상품·법령 조항과 무관하다.
- 설계자가 정책, 탐지기, `dev`, `test`를 모두 쓰므로 같은 가정을 공유한다. 이 편향은 `redteam`과
  독립 라벨러 일치도로 *부분적으로만* 확인한다. 독립 에이전트는 사람이 아니라 별도 컨텍스트의 LLM이다.
- `test` 동결 후 수정은 **라벨 오류**에 한정한다. 탐지기를 통과시키려는 수정은 하지 않는다. 수정하면 CHANGELOG에 사유를 남긴다.

## 3. 지표

`N`은 소재 수, `N_R / N_V / N_A`는 정답이 REJECT / REVIEW / APPROVE인 소재 수.

| 지표 | 정의 |
|---|---|
| `hard_pass_through` | 정답이 REJECT인데 APPROVE로 판정한 비율 = #(예측 APPROVE ∧ 정답 REJECT) / N_R |
| `unsafe_approve` | 정답이 REJECT 또는 REVIEW인데 APPROVE로 판정한 비율 = #(예측 APPROVE ∧ 정답 ∈ {REJECT, REVIEW}) / (N_R + N_V) |
| `false_reject` | 정답이 APPROVE인데 REJECT로 판정한 비율 = #(예측 REJECT ∧ 정답 APPROVE) / N_A |
| `over_review` | 정답이 APPROVE인데 REVIEW로 판정한 비율 |
| `auto_rate` | 사람에게 가지 않은 비율 = #(예측 ∈ {APPROVE, REJECT}) / N |
| `auto_precision` | 자동 판정 중 정답과 같은 비율 |
| `accuracy`, `macro_f1` | 3클래스 판정 |
| `rule_f1` | (소재, 규칙 ID) 쌍 단위 micro P/R/F1. AD-FMT-01 제외 |
| `localization` | 맞춘 (소재, 규칙) 쌍 중 정답 인용과 예측 인용이 같은 필드에서 겹치는 비율 (인용이 있는 규칙만) |
| `fin_missing_exact` | 맞춘 AD-FIN-01 쌍 중 `missing` 집합이 정확히 같은 비율 |
| `grounding` | 인용이 있는 예측 중, 인용이 원문 필드의 `[start:end]`와 정확히 같은 비율 |
| `latency_ms` | 소재당 처리 시간 p50 / p95 (결정론 경로) |

모든 비율은 분모와 함께 적고, 분모가 작은 지표에는 Wilson 95% 구간을 붙인다.
**정답이 작은 셋(분모 20~30)에서는 한 건이 3~5%p를 움직인다.** 구간을 함께 읽는다.

## 4. 합격 기준 (`test`, 사전등록)

| ID | 기준 | 종류 |
|---|---|---|
| H1 | `hard_pass_through` = 0 | 필수 |
| H2 | `grounding` = 100 % | 필수 |
| H3 | `unsafe_approve` ≤ 3 % | 필수 |
| S1 | `false_reject` ≤ 5 % | 목표 |
| S2 | `over_review` ≤ 10 % | 목표 |
| S3 | `auto_rate` ≥ 70 % | 목표 |
| S4 | `rule_f1` ≥ 0.85 | 목표 |
| S5 | 베이스라인 B1보다 `unsafe_approve`와 `false_reject`가 **둘 다** 낮다 | 목표 |

- 필수를 하나라도 못 지키면 "배포 가능"이라 쓰지 않고 미달로 적는다. 목표 미달은 미달로 적는다.
- `redteam`(첫 측정)은 합격 기준이 없다. 사전 예상만 적는다: `unsafe_approve` ≤ 15 %. 틀려도 그대로 기록한다.

## 5. 비교 대상과 어블레이션

| 이름 | 내용 |
|---|---|
| B0 | 전부 사람에게 보낸다. `auto_rate` = 0, `unsafe_approve` = 0. 사람 부담의 상한 |
| B1 | 순진한 키워드 블록리스트. 정책 문서의 위반 예 단어(30개 안팎)를 원문 부분 문자열로 찾고, 하나라도 있으면 REJECT, 없으면 APPROVE |
| 전체 | 이 저장소의 파이프라인(결정론 경로) |
| `-normalize` | 우회 정규화 끔 |
| `-exceptions` | 부정문·범위 표현·면책 고지·근거 표시 예외 끔 |
| `-challenge` | 도전자(느슨한 두 번째 검사) 끔 |
| `-landing` | 광고-랜딩 대조 끔 |

각 구성요소를 끌 때 지표가 얼마나 나빠지는지가 그 구성요소가 한 일이다. 하나도 나빠지지 않으면 평가셋이 그것을 덮지 못한다는 뜻이고 그렇게 적는다.

## 6. 게이트와 열화 대조군

- CI는 `dev`와 `test`에서 위 지표를 다시 계산해 커밋된 기준선(`artifacts/baseline.json`)과 비교한다. 필수 기준 위반 또는 기준선 대비 악화(허용 오차 0.5%p)면 실패한다.
- **열화 대조군**: 위 어블레이션 구성을 일부러 켠 상태로 게이트를 돌려 *실패해야* 정상이다. 실패하지 않는 구성은 게이트가 그 구성요소를 감시하지 못한다는 뜻이며 gap으로 기록한다.

## 7. 측정 프로토콜

1. `dev`는 자유롭게 본다. 규칙·패턴은 `dev` 오류를 보고 고친다.
2. 코드를 동결한 뒤 `test`를 측정한다. 측정 횟수와 git 커밋을 [MEASUREMENTS.md](MEASUREMENTS.md)에 남긴다.
3. `test`를 보고 코드를 고쳤다면 이후 `test` 수치는 "순수 holdout이 아님"이라고 표기한다.
4. `redteam`은 독립 에이전트가 작성하고, **수정 전 첫 측정 수치**를 보존한다. 이후 수정한 뒤의 수치는 따로 적고 holdout이 아니라고 표기한다.
5. 독립 라벨러(별도 에이전트)가 정책 문서만 보고 `test`·`dev` 소재에 판정과 규칙을 붙인다. 판정 Cohen's κ와 규칙 단위 일치도를 낸다.
   κ < 0.6이거나 특정 규칙에서 불일치가 몰리면 정책 문구가 모호한 것으로 보고 문서를 고친다. 고친 내용과 이유를 기록한다.
   독립 라벨러의 판독이 정책 문구에 더 잘 부합할 때만 정답 라벨을 바꾼다.
6. 수치는 산출물(JSON)에서 스크립트가 문서에 채운다. 손으로 옮겨 적지 않는다.

## 8. LLM 경로

- 기본 경로는 결정론이다. LLM judge는 선택 사항이며, 키 없이는 실행하지 않는다.
- 이 저장소의 환경에서는 LLM을 호출할 수 없다. LLM 경로의 **정확도·비용·지연은 측정하지 않으며**, 어댑터의 요청·응답 계약과
  안전장치(근거 검증, 판정 필드 부재, 장애 시 fail-closed)만 시험한다. 측정은 `make eval-llm`으로 키를 넣고 별도로 한다.

## 9. 주장하지 않는 것

- 실제 광고 데이터에서의 정확도, 실제 심사자와의 일치도, 사람 심사 시간의 절감.
- 법적 적합성. 이 정책표는 가상이다.
- 이미지를 직접 이해하는 능력. `image_text`는 업스트림이 준 값이라고 가정한다.
- LLM 경로의 성능.
