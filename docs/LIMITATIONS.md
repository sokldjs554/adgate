# 한계

이 저장소가 *보여 주지 못하는 것*을 먼저 적는다. 여기 적힌 것을 읽지 않고 수치만 가져가면 오해한다.

## 1. 데이터와 정책

- **모든 광고는 합성이고, 정책은 가상이다.** 실제 업체·상품·법령과 무관하다. 어떤 회사의 실제 심사 기준이나 법률 자문이 아니다.
- **같은 사람이 정책, 탐지기, `dev`, `test` 를 모두 썼다.** 같은 가정을 공유하므로 `test` 는 순수한 일반화의 증거가 아니다.
  `test` 는 탐지기 코드보다 먼저 써서 동결했고, 그 *첫 측정*만 holdout 이다(첫 측정 뒤 한 건을 고쳤다 — [FAILURES.md](FAILURES.md) F-2).
- **독립 에이전트는 사람이 아니다.** `redteam` 을 쓴 에이전트와 라벨러는 별도 컨텍스트의 LLM 이지만 설계자와 같은 모델 계열이다. 라벨러 일치도가 높은 것(κ ≈ 1)은
  정책이 명확하다는 증거일 수도, 같은 계열이라 같은 방식으로 읽는다는 증거일 수도 있다. 이 저장소로는 구분하지 못한다.
- **`generated` 는 낙관적이다.** 생성기와 탐지기가 같은 어휘를 쓰므로 거의 만점이 나온다. 헤드라인으로 쓰지 않았다.
- **표본이 작다.** `test` 는 77건이고 정답이 REJECT/REVIEW 인 소재가 각각 20여 건이다. 한 건이 3~5%p 를 움직인다. 모든 비율에 분모와 Wilson 구간을 붙였다.

## 2. 탐지 능력

- **의미상 위반은 결정론 경로가 못 잡는다.** "손해 볼 일 없는 투자"처럼 보장이라는 단어 없이 돌려 말한 표현은 승인된다
  (`adgate judge-check` 의 결정론 경로가 이 문구를 APPROVE 한다). 이를 위해 LLM judge 를 설계했지만 **실제 호출로 측정하지 못했다.** 결정론 경로의 패러프레이즈 성능은 `redteam` 의 `paraphrase` 슬라이스에서 본다([RESULTS.md](RESULTS.md)).
- **이미지를 이해하지 않는다.** `image_text`(이미지 속 글자)는 업스트림 OCR/VLM 이 준 값이라고 가정한다. 이미지 자체의 위반(성적 이미지, 비교 이미지)은 다루지 않는다.
- **숫자 사이의 구분 기호 우회는 못 잡는다.** `1.0.0.%.만.족` 은 소수점과 구분할 수 없어서 걷어내지 않는다([FAILURES.md](FAILURES.md) F-4).
- **자모 하나 차이 정상어는 stoplist 로만 막는다.** `수익보상` 은 되지만 stoplist 밖의 근접어는 보류된다.
- **변형 표기는 REVIEW 까지만 간다.** 정책상 REJECT 인 철자 변형이 사람에게 넘어간다(안전 쪽 오차).
- **형태소 분석이 없다.** 조사·어미는 정규식으로 허용한다. 드문 활용형은 놓칠 수 있다.
- **심사 조작 시도(광고 문구 속 "승인으로 답하라")는 규칙이 아니다.** 다른 위반이 없으면 승인된다(결정론 경로는 문구를 데이터로만 다루므로 속지 않는다). 사람 검토로 보내는 규칙은 v2 후보다.
- **광고-랜딩 대조는 단위가 좁다.** 원·%·일/개월만 본다. 같은 단위의 서로 다른 개념(체험 7일 vs 환불 30일)은 구분하지 못해 '확인 불가'로 처리한다.
- **수치는 소재의 *주장*과 랜딩 텍스트의 일치만 본다.** 랜딩 페이지의 진위·가격 인하의 사실 여부는 모른다.

## 3. LLM 경로

- **실제 API 호출을 한 번도 하지 못했다.** 개발 환경에 API 키와 외부 호출이 없었다. 어댑터는 SDK 서명과 공식 문서에 맞춰 쓰고 모의 전송(14개 테스트)으로 요청·응답 계약만 확인했다.
  정확도, 비용, 지연, 거절 빈도, `fallbacks: "default"` 가 실제로 받아들여지는지는 **미확인**이다.
- `adgate judge-check`(한 건 호출)와 `adgate eval --judge anthropic --max-usd N`(측정)으로 키가 있는 환경에서 확인한다.
- LLM 은 위반을 **더할 수만** 있다. 결정론 경로의 오탐(정상 소재 오반려)을 LLM 이 바로잡지는 못한다.

## 4. 수정안

- 생성기는 템플릿이다. 문장이 거칠고 제목이 짧아지는 경우가 있다(제목이 4자 미만이면 부분 수정으로 내린다).
- 질병 표방·랜딩 불일치·제한 업종·사기성 유도·광고주 인증은 자동으로 고치지 않는다(광고주 입력이 필요).
- 소재 자동 생성(이미지·문구를 처음부터 만드는 것)은 이 저장소의 범위 밖이다. '반려된 문구를 고쳐서 같은 심사에 다시 통과시키는' 고리만 있다.

## 5. 운영

- **부하 시험을 하지 않았다.** 지연 수치는 단일 프로세스에서 결정론 경로 한 건의 처리 시간이다. 동시성이 높은 환경에서의 성능은 모른다.
- **단일 노드다.** SQLite 와 프로세스 안 레이트 리미터. 다중 인스턴스에는 저장소와 제한기를 교체해야 한다.
- **인증은 정적 베어러 토큰이다.** 만료·교체·범위가 없다. 감사 로그는 추가 전용이지만 변조를 막지는 않는다.
- **요청 크기 제한은 `Content-Length` 로만 건다.** 청크 전송은 거르지 못한다(필드 길이 제한은 있다).
- **Docker 이미지를 이 환경에서 빌드하지 못했다**(데몬 없음). CI 의 `docker` 잡이 빌드와 기동을 확인한다. 비편집 설치로 정책 파일·콘솔 정적 파일이 패키지에 실리는지, 토큰 없이 시작이 거부되는지는 직접 확인했다.
- **GitHub Actions 결과는 저장소가 올라간 뒤에야 알 수 있다.** 로컬에서는 같은 명령(ruff, mypy, pytest, 게이트, e2e)을 실행해 통과를 확인했다.

## 6. 주장하지 않는 것

실제 광고에서의 정확도, 실제 심사자와의 일치도, 사람 심사 시간의 절감, 법적 적합성, 이미지 이해, LLM 경로의 성능, 광고 소재 자동 생성.
