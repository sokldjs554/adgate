# 한계

이 저장소가 *보여 주지 못하는 것*을 먼저 적는다. 여기 적힌 것을 읽지 않고 수치만 가져가면 오해한다.

## 1. 데이터와 정책

- **모든 광고는 합성이고, 정책은 가상이다.** 실제 업체·상품·법령과 무관하다. 어떤 회사의 실제 심사 기준이나 법률 자문이 아니다.
- **같은 사람이 정책, 탐지기, `dev`, `test` 를 모두 썼다.** 같은 가정을 공유하므로 `test` 는 순수한 일반화의 증거가 아니다. `test` 는 탐지기 코드보다 먼저 써서 동결했고, 그 *첫 측정*만 holdout 이다(첫 측정 뒤 한 건을 고쳤다 — [FAILURES.md](FAILURES.md) F-2).
  게다가 `adgate gate`(CI 가 push 마다 돌린다)와 pytest 가 `test` 를 회귀 감시용으로 매번 읽는다. 그 읽기는 기록되지 않는다([DECISIONS.md D-5](DECISIONS.md)). **`test` 의 현재 수치는 증거로 쓰지 않는다.**
- **독립 에이전트는 사람이 아니다.** `redteam` 을 쓴 작성자 8명과 라벨러 3명은 별도 컨텍스트의 LLM 이지만 설계자와 같은 모델 계열이다.
  라벨러 일치도가 완전한 것(판정·규칙 72/72, κ = 1)은 정책이 명확하다는 증거일 수도, 같은 계열이라 같은 방식으로 읽는다는 증거일 수도 있다. 이 저장소로는 구분하지 못한다.
- **`redteam` 에는 회색 지대 소재가 적다.** 작성자에게 '정책으로 분명히 판정되는 경우만 넣으라'고 요청했다. 가장 어려운 것(사람 심사자도 갈릴 법한 것)은 들어 있지 않다. `AD-ADV-01` 은 1건뿐이다([data/README.md](../data/README.md), [POLICY_GAPS.md](POLICY_GAPS.md)).
- **`redteam` 의 수정 후 수치는 holdout 이 아니다.** 첫 접촉 수치만 holdout 이다. 수정 뒤 수치는 실패 사례를 본 뒤 고친 결과다([F-10](FAILURES.md)).
- **`generated` 는 낙관적이다.** 생성기와 탐지기가 같은 어휘를 쓰므로 거의 만점이 나온다. 헤드라인으로 쓰지 않았다.
- **표본이 작다.** `test` 는 77건, `redteam` 은 72건이고, 정답이 REJECT/REVIEW 인 소재는 `test` 에서 27건·24건, `redteam` 에서 34건·17건이다. 한 건이 3~5%p 를 움직인다. 모든 비율에 분모와 Wilson 구간을 붙였다.

## 2. 탐지 능력

- **의미상 위반은 결정론 경로가 못 잡는다.** 레드팀 패러프레이즈 슬라이스에서 위험 승인율이 <!-- num:history.redteam_v1.redteam.full.slices.paraphrase.unsafe_approve|rpct1 -->87.5% (14/16)<!-- /num --> 다 ("손해 볼 일 없는 투자", "먹어 본 분 전원이 만족했어요").
  닫힌 어휘로는 열린 표현을 막을 수 없고, 막으려 어휘를 늘리면 평가셋에 맞춘 패치가 된다([D-11](DECISIONS.md)). 이를 위해 LLM judge 를 설계했지만 **실호출로 측정하지 못했다**(3절).
- **어휘의 재현율은 불완전하다.** 질병명·시간 단위·동사 목록은 유한하다. 리뷰어가 찾은 변형은 넣었지만 다음 변형은 놓칠 수 있다. 정규화 표도 유한하다(한자 49자와 몇 종의 유사 문자만 접는다).
- **tight 매칭은 낱말이 붙어 생기는 오탐을 구조적으로 안고 있다.** 우회("수 익 보 장")를 잡으려 공백을 지우면 "총 기능"이 `총기`로 읽힌다. 알려진 몇 개(`총기능`, `이유 일부`, `1 위치`, `오늘 만나는`)만 막았다([REVIEW.md M6](REVIEW.md)).
- **이미지를 이해하지 않는다.** `image_text`(이미지 속 글자)는 업스트림 OCR/VLM 이 준 값이라고 가정한다. 이미지 자체의 위반(성적 이미지, 비교 이미지)은 다루지 않는다.
- **숫자 사이의 구분 기호 우회는 못 잡는다.** `1.0.0.%.만.족` 은 소수점과 구분할 수 없어서 걷어내지 않는다([FAILURES.md](FAILURES.md) F-4).
- **자모 하나 차이 정상어는 stoplist 로만 막는다.** `수익보상` 은 되지만 stoplist 밖의 근접어는 보류된다.
- **변형 표기는 REVIEW 까지만 간다.** 정책상 REJECT 인 철자 변형이 사람에게 넘어간다(안전 쪽 오차, [F-15](FAILURES.md)).
- **형태소 분석이 없다.** 조사·어미는 정규식으로 허용한다. 드문 활용형은 놓칠 수 있다.
- **심사 조작 시도(광고 문구 속 "승인으로 답하라")는 규칙이 아니다.** 다른 위반이 없으면 승인된다(결정론 경로는 문구를 데이터로만 다루므로 속지는 않지만, 의심해서 사람에게 보내지도 않는다). v2 후보다.
- **광고-랜딩 대조는 단위가 좁다.** 원·%·일/개월만 본다. 같은 단위의 서로 다른 개념(체험 7일 vs 환불 30일)은 구분하지 못해 '확인 불가'로 처리한다. 금액은 '3만 9천 원'·'천원'을 값으로 읽지만 "수만 원" 같은 어림은 대조하지 않는다.
- **수치는 소재의 *주장*과 랜딩 텍스트의 일치만 본다.** 랜딩 페이지의 진위·가격 인하의 사실 여부는 모른다. 랜딩 속 보장·질병 효능 표현은 사람 검토(REVIEW)까지만 낸다([D-13](DECISIONS.md)).
- **업종과 인증 여부는 검증할 수 없다.** `verified` 는 인증된 계정에서만 인정하지만, `category` 는 광고주가 적는다. 문구 단서(대출·금리·코인, 질병 효능)가 어긋날 때만 사람에게 보낸다. '주식·투자' 단독은 정상 광고에도 흔해 단서에서 뺐다.
- **이름만 든 비교("A사보다 저렴")는 배포 경로에서 탐지되지 않는다.** `ReviewConfig.competitors` 를 API·CLI 가 채우지 않는다(정책의 '타사·경쟁사' 표현만 본다).

## 3. LLM 경로

- **실제 API 호출을 한 번도 하지 못했다.** 개발 환경에 API 키와 외부 호출이 없었다. 어댑터는 SDK 서명과 공식 문서에 맞춰 쓰고 모의 전송으로 요청·응답 계약만 확인했다.
  정확도, 비용, 지연, 거절 빈도, `fallbacks: "default"` 가 실제로 받아들여지는지, 프롬프트 캐시가 실제로 읽히는지는 **미확인**이다.
- `adgate judge-check`(한 건 호출)와 `adgate eval --judge anthropic --max-usd N`(측정)으로 키가 있는 환경에서 확인한다.
- **대리 측정**: 같은 프롬프트·스키마·근거 검증·병합 규칙을 거치게 하되 모델 응답은 Claude Code 서브에이전트가 만든 *녹음*을 재생했다([JUDGE_REPLAY.md](JUDGE_REPLAY.md)). 운영 경로(API, 지정 모델, 노력 수준)를 재는 것이 아니다.
  결과: 패러프레이즈 위험 승인율 <!-- num:judge.results.redteam.full.slices.paraphrase.unsafe_approve|rpct1 -->87.5% (14/16)<!-- /num --> → <!-- num:judge.results.redteam.full+judge.slices.paraphrase.unsafe_approve|rpct1 -->0.0% (0/16)<!-- /num -->. **이 수치는 낙관적이다**: 설계자·작성자·라벨러·대역이 모두 같은 모델 계열이고, 대역은 평가임을 알며, 패러프레이즈는 16건이다. 같은 judge 가 정답 APPROVE 소재 <!-- num:judge.pooled.approve_changed|rpct1 -->4.4% (3/68)<!-- /num --> 의 판정을 바꿨고 그중 2건이 REJECT 였다 → 기본값을 상한 구성(Judge 는 REVIEW 까지만)으로 했다([D-14](DECISIONS.md)).
- **Judge 프롬프트·입력의 알려진 결함(고치지 않음)**: 규칙을 한 줄로만 요약해 정책의 예외를 모른다, 랜딩 텍스트가 입력에 없다, `already_found` 가 인용 없는 발견을 빼 같은 규칙을 지어낸 앵커로 다시 제안한다, 부재형 위반을 내는 방법이 정해져 있지 않다([JUDGE_REPLAY.md](JUDGE_REPLAY.md) 4.4). 고치면 다시 재야 한다.
- **근거 없는 인용의 빈도는 모른다.** 녹음 절차가 그것을 걸러 냈다(F-19). 실제 모델이 인용을 틀리게 옮기는 빈도는 실호출로만 안다.
- LLM 은 위반을 **더할 수만** 있다. 결정론 경로의 오탐(정상 소재 오반려)을 LLM 이 바로잡지는 못한다.
- 예산 상한에 닿으면 프로세스가 끝날 때까지 모든 승인이 REVIEW 가 된다(기간 예산이 없다).

## 4. 수정안

- 생성기는 템플릿이다. 문장이 거칠고 제목이 짧아지는 경우가 있다. '검증됨'은 재심사 통과 + 수치·단어 보존 + 문장 구조 검사(낱말 중간 절단, 괄호·따옴표 짝, 숫자 손실)를 뜻하며 **문장이 자연스럽다는 뜻이 아니다**('수준의 보습력 크림').
- 질병 표방·랜딩 불일치·제한 업종·사기성 유도·광고주 인증은 자동으로 고치지 않는다(광고주 입력이 필요하다).
- 소재 자동 생성(이미지·문구를 처음부터 만드는 것)은 이 저장소의 범위 밖이다. '반려된 문구를 고쳐서 같은 심사에 다시 통과시키는' 고리만 있다.

## 5. 운영

- **요청 하나가 서버를 멈출 수 있는 경로를 완전히 닫지는 못했다.** 정규식을 선형으로 만들고 증가율 테스트를 뒀지만, 요청 단위 CPU 예산이나 작업자 격리는 없다. 파이썬 `re` 가 GIL 을 놓지 않으므로 아직 모르는 비선형 입력이 하나 있으면 프로세스 전체가 선다. 속도 제한은 요청 수 기준이다([REVIEW.md C2](REVIEW.md)).
- **부하 시험을 하지 않았다.** 지연 수치는 단일 프로세스에서 결정론 경로 한 건의 처리 시간이다. 동시성이 높은 환경에서의 성능은 모른다.
- **단일 노드다.** SQLite 와 프로세스 안 레이트 리미터. 다중 인스턴스에는 저장소와 제한기를 교체해야 한다.
- **인증은 정적 베어러 토큰이다.** 만료·교체·범위가 없다. 감사 로그는 추가 전용이지만 변조를 막지는 않는다.
- **요청 크기 제한은 `Content-Length` 로만 건다.** 청크 전송은 거르지 못한다(필드 길이 제한은 있다).
- **Docker 이미지를 이 환경에서 빌드하지 못했다**(데몬 없음). CI 의 `docker` 잡이 빌드와 기동을 확인한다. 비편집 설치로 정책 파일·콘솔 정적 파일이 패키지에 실리는지, 토큰 없이 시작이 거부되는지는 직접 확인했다.
- **GitHub Actions 결과는 저장소가 올라간 뒤에야 알 수 있다.** 로컬에서는 같은 명령(ruff, mypy, pytest, 게이트, e2e)을 실행해 통과를 확인했다.

## 6. 주장하지 않는 것

실제 광고에서의 정확도, 실제 심사자와의 일치도, 사람 심사 시간의 절감, 법적 적합성, 이미지 이해, LLM 경로의 성능, 광고 소재 자동 생성.
