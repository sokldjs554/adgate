# 회색지대 judge 측정: 구현 세부 사전등록 (v1 · v2 · 신뢰도 문턱)

이 문서의 **1–5절은 측정 전에 쓴 것**이고 해시를 `docs/PREREGISTRATIONS.json` 이 고정한다(`adgate prereg`). 가설(E3–E5)과 판단 규칙(R1·R2)은 [EVAL_GRAY.md](EVAL_GRAY.md) 3–4절이 이미 정했다 — 여기서는 *구현이 그 가설을 어떻게 재는지*를 못 박는다.
결과는 6절 이후에 덧붙인다. 구현은 `src/adgate/judge_llm.py`(Judge · 정책 조항 검색), `src/adgate/judge_suite.py`(측정 묶음 `judge_gray`).

## 1. 두 구성

| 구성 | 내용 |
|---|---|
| **v1** | `judge_anthropic` 의 시스템 프롬프트·출력 스키마·사용자 메시지를 *글자 그대로* 쓴다([JUDGE_LIVE.md](JUDGE_LIVE.md) 와 같은 프롬프트; 시험이 문자열 동일성을 검사한다). 호출만 공통 LLM 계층(`adgate.llm`)을 탄다 |
| **v2** | v1 과 같은 스키마·같은 방어 문구에 **정책 조항 검색**을 더한다. 시스템 프롬프트는 소재와 무관하게 고정이고(캐시된다), 사용자 메시지 앞에 `<policy_clauses>` 로 조항 전문이 붙는다 |

모델 `claude-opus-5-5`, effort `medium`, `max_tokens` 16000 — 두 구성 모두 같다. 소재당 한 번(`judge.propose`).

**검색(v2).** 코퍼스는 `docs/POLICY.md` 를 쪼갠 조항이다: 4절의 규칙마다 하나(AD-FMT-01 은 등급이 모두 info 라 뺀다), 8절의 해석 규칙마다 하나(`해석-8.1`…`8.8`). 색인은 글자 이분 조각의 TF-IDF(`log((N+1)/(df+1))+1`, 빈도 `1+log c`) 코사인 유사도다 — 임베딩이 없고 어휘 기반이다.
질의는 소재의 `headline · body · cta · disclosure · image_text` 이어 붙임이다(랜딩 제외). 선택: 업종에 적용되는 규칙 조항 중 점수 상위 **4개** + 결정론 경로가 이미 발견한 규칙의 조항(점수와 무관) + 공통 해석 규칙 `해석-8.2`(뜻이 기준이다)·`해석-8.7`(경고는 위반이 아니다).
**k=4 와 이 선택 규칙은 이 셋을 보기 전에 정했다.** 모든 규칙의 한 줄 요약은 v1 처럼 시스템 프롬프트에 그대로 있어서, 검색이 놓친 규칙도 모델이 보고할 수 있다.

## 2. 한 사례에서 재는 네 구성

같은 호출은 한 번만 녹음되고 나머지는 재생된다(문턱은 후처리라 추가 호출이 없다).

| 구성 | 내용 |
|---|---|
| `full` | 결정론 경로(judge 없음) — **그 뒤 수정을 거친 현재 엔진**이다. 첫 접촉(E1)은 `artifacts/history/gray_first_contact.json` 에 따로 보존돼 있다 |
| `judge` | judge 발견이 정책 등급 그대로 |
| `cap` | judge 발견은 REVIEW 까지만(기본값, D-14) |
| `cap_theta` | `cap` + 신뢰도가 **0.65 미만**인 제안을 근거 검증 전에 뺀다. 0.65 는 EVAL_GRAY E5 가 이 셋을 보기 전에 정한 값이다 |

judge 입력에는 결정론 경로의 `already_found` 가 들어간다. 그래서 **엔진을 바꾸는 일을 모두 마친 뒤에 녹음한다**(엔진이 바뀌면 열쇠가 바뀌어 낡은 녹음이 재생되지 않는다).

## 3. 지표 (정의는 `judge_suite.effects`)

- **오탐**: 정답 APPROVE 소재 중 `full` 과 판정이 달라진 비율. 그중 REJECT 가 된 것은 따로 센다.
- **회수**: `full` 이 APPROVE 로 놓친 위험 소재(정답 REJECT·REVIEW) 중 APPROVE 가 아니게 된 비율.
- **위험 승인율 상대 감소**: `(full 의 위험 승인율 − 구성의 위험 승인율) / full 의 위험 승인율`.
- **검색 재현율@k**(v2): 정답 위반의 규칙 중 검색된 조항에 든 비율 — 전체와, 결정론이 놓친 규칙만(이쪽이 검색이 실제로 더하는 것).
- 구성별 정확도·위험 승인율·정상 오반려·정상 오보류·규칙 F1, 슬라이스(clear / normal / gray / disputed), judge 호출 실패·근거 없는 의심 소재 수.
- E3·E4·E5 의 비교는 모두 `cap`(기본 구성) 위에서 한다. `judge`(상한 없음)는 보조로 낸다.

모든 비율에 분모를 쓰고 Wilson 95% 구간을 붙인다. 표본이 작다: 정답 APPROVE 50건, 위험 소재 70건.

## 4. 추가 사전 예상

E3–E5 는 EVAL_GRAY.md 에 있다. 아래는 구현 세부에서 새로 나온 예상이다. 틀려도 고치지 않고 '빗나감'이라 쓴다.

| # | 예상 | 확률(내 믿음) |
|---|---|---|
| J1 | 검색 재현율@4(전체) **≥ 0.80**, 결정론이 놓친 규칙만 **≥ 0.60**(어휘 검색이라 돌려 말한 위반의 조항을 덜 가져온다) | 55% |
| J2 | v2 호출의 입력 비용이 v1 보다 **30–90%** 많다(조항 전문이 붙는다) | 70% |
| J3 | judge 호출 실패(거절·잘림·형식 오류·시간 초과)가 있는 소재는 구성마다 **≤ 3%** | 65% |
| J4 | `cap` 구성에서 정답 APPROVE 가 REJECT 로 바뀌는 소재는 **0건**(상한 때문에 구조상 불가능) | 99% |
| J5 | θ=0.65 를 v2 에 걸어도 오탐 상대 감소 **≥ 30%**(탐색적; v1 에서 성립해도 v2 에서는 확률이 낮다) | 35% |

## 5. 프로토콜 (순서)

1. 이 문서와 구현(`judge_llm.py` · `judge_suite.py` · 시험)을 한 커밋으로 등록한다. 그 뒤 프롬프트·검색·문턱·지표 정의를 바꾸지 않는다.
2. 심사 엔진을 바꾸는 작업(다른 평가의 실패 분석에서 나오는 문형·표기 수정)을 모두 끝내고 게이트(`adgate gate`)가 통과한 *뒤에* 녹음한다. `full` 은 그 엔진이다.
3. `adgate llm dry-run judge_gray` 로 비용을 낸다 → 사용자 승인 → `llm-live` 로 v1·v2 를 녹음 → 깨끗한 작업트리에서 재생·집계 → 첫 접촉 보존 → 6절 이후.
4. E4·R1(v2 채택)과 E5·R2(문턱 채택)는 EVAL_GRAY.md 4절 그대로 판단한다. 채택은 코드 기본값을 바꾸는 것이고, 바꾸면 게이트와 열화 대조군을 다시 돌린다.

## 6. 주장하지 않는 것

이 정책은 작다(조항 전체가 수천 자). 조항 전체를 프롬프트에 넣는 방식이 검색보다 단순하고 싸다 — 검색의 가치는 정책이 커질 때 나오고 여기서는 그 *메커니즘*(검색 → 조항을 보고 예외 판단)만 잰다. 임베딩 검색, 재순위화, 조항 수가 많은 정책에서의 재현율은 재지 않았다.
작성자·라벨러·judge 가 같은 모델 계열이라 낙관 편향이 남는다. 120건의 회색지대 셋에서 v1·v2 의 차이가 잡음인지는 구간으로만 가를 수 있다.
