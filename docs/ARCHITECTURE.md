# 구조

한 줄 요약: **모델은 제안하고 코드가 검증한다. 어느 모듈에서나 모델의 출력은 *근거(원문 인용·사실 ID·계산한 숫자)가 있을 때만* 다음 단계로 넘어가고, 판정과 흐름 제어는 결정론 코드가 한다.**
모든 광고·상품·광고주는 합성이고 정책은 가상이다. 이 문서는 구현의 지도이고, 수치는 [RESULTS.md](RESULTS.md)·`EVAL_*.md` 에 있다.

## 1. 모듈과 이음새

```
              ┌────────────┐   사양(슬롯+출처+인용)   ┌────────────┐  광고 후보  ┌────────────┐  판정·사유·수정안
광고주의 말 ─▶│ campaign/  │─────────────────────────▶│ creative/  │────────────▶│  review()  │───────────────▶ 심사자 대기열
(자연어 대화) │ 셋업 대화  │      (업종·목표·랜딩)    │ 소재 생성  │  게이트 안  │ (결정론 엔진)│  rewrite() 재심사   (waiting_input)
              └────────────┘                          └─────┬──────┘             └─────▲──────┘
                                       상품 페이지·이미지 ──▶│ vision/ 이미지 읽기(글자·단서)                │ Judge(선택): 제안만
                                                            └────────────────────────────────────────────────┘
집행 중 일별 지표 ─▶ insight/ 이상 탐지 → 원인 진단 → 액션 → 사실에 묶인 리포트 ──▶ "반려 소재 수정" ─▶ rewrite() 로 이어진다 (데모: adgate demo)
                                   ops/ 운영 리허설(격리·드리프트·섀도·번레이트·부하) · catalog/ 라벨링·사람 실험 · eval/ 평가 하니스·게이트
```

| 모듈 | 입력 → 출력 | 모델이 하는 일 | 코드가 하는 일(검증·판정) | 평가 문서 |
|---|---|---|---|---|
| `campaign/` | 광고주 발화 → 캠페인 사양(슬롯, 출처 user/derived/assumed, 인용) | 발화에서 슬롯 후보 추출, (선택) 답변 다듬기 | 인용이 발화에 글자 그대로 있는가, 값 형식, 주입 문장의 값 버림, 검증기 오류·경고, 질문 우선순위(최대 둘), 요약 → 확인 뒤에만 ready, 가정값 표시 | [EVAL_SETUP.md](EVAL_SETUP.md) |
| `vision/` | 광고·상품 이미지 → 글자 덩어리·시각 단서 | 이미지 읽기(구조화 출력) | 읽기 실패는 승인으로 이어지지 않음(REVIEW), 읽은 글자는 *데이터*로만 심사에 들어감 | [EVAL_VISION.md](EVAL_VISION.md) |
| `creative/` | 상품 페이지(HTML)·이미지·광고주·브랜드 보이스 → 광고 후보 | 사실 추출(원문 인용 필수), 후보 생성, 수리 | 숨은 글 제거, 지시 문장 정화, 인용 검증, 사실 심사, 후보 검증(숫자·길이·브랜드·어조), 심사 게이트, 계정 차단(미인증 대출·투자, 성인·도박) | [EVAL_CREATIVE.md](EVAL_CREATIVE.md) |
| `review()` (`pipeline.py` 외) | 광고 한 건 → 승인·반려·보류 + 사유(규칙·원문 인용·수정 방법) | (선택) Judge 가 위반 *후보*를 제안 | 정규화(오프셋 보존) → 규칙 12개 → 도전자(REVIEW 까지) → 병합·판정(최고 등급). 인용이 없는 제안은 발견이 못 된다 | [RESULTS.md](RESULTS.md) |
| `rewrite.py` | 반려·보류 광고 → 수정안 + 재심사 결과 | — (템플릿) | 자동으로 고칠 수 있는 위반만, 재심사 APPROVE·수치 보존·문장 건전성을 통과해야 '검증됨' | [RESULTS.md](RESULTS.md) |
| `insight/` | 일별 지표·변경 이력 → 경보·원인·액션·리포트 | (선택) 리포트 문단 작성 | 같은 요일 기준선, 이틀 연속 조건, 신호 서명 진단, 기대효용 액션, 리포트의 모든 문단은 사실 ID 인용 + 숫자 근거·금지 액션 검사 | [EVAL_INSIGHT.md](EVAL_INSIGHT.md) |
| `ops/` | 트래픽·판정 로그 → 운영 신호 | — | judge 장애 격리(시간 제한·벌크헤드·회로 차단기), 라벨 없는 드리프트 모니터, 섀도 승격 게이트(안전 방향 손실), 번레이트 경보, 부하 리허설 | [EVAL_OPS.md](EVAL_OPS.md) |
| `catalog/` | 판정 로그·사람 검토 → 라벨링 큐·중재·실험 키트 | — | 이중 라벨 + 세 번째 중재, 사람 실험(교차 설계) 키트와 분석, 운영 환류 | [EVAL_LABELING.md](EVAL_LABELING.md) · [STUDY_PROTOCOL.md](STUDY_PROTOCOL.md) |

이음새 — 한 모듈의 출력이 다음 모듈의 입력이 되는 곳 — 의 검사는 [DEMO.md](DEMO.md) 가 전사와 이음새 검사로 보인다(데모이지 측정이 아니다).

## 2. 신뢰 경계

| 데이터 | 신뢰 | 어떻게 다루나 |
|---|---|---|
| 광고 문구·상품 페이지·이미지 속 글자·광고주 발화 | **신뢰하지 않는다**(데이터) | 모델 입력에는 *데이터로 감싸* 넣고, 지시처럼 보이는 문장은 정화하거나 값을 버린다. 심사 엔진은 결정론이라 글자가 엔진의 동작을 바꾸지 못한다 |
| 모델의 출력 | **제안** | 판정 필드가 스키마에 없다. 근거(인용·사실 ID·숫자)를 코드가 원문과 대조해 통과한 것만 쓴다. 실패·거절·잘림·형식 오류는 fail-closed(승인하지 않음) |
| 정책·정답·사전등록 문서 | 고정 | 해시로 동결(`data/MANIFEST.sha256`, `docs/PREREGISTRATIONS.json`). 고치려면 사유를 남기고 명령에 플래그가 필요하다 |

## 3. 공통 LLM 계층 (`src/adgate/llm/`)

모든 모델 호출은 *과제(task) 하나 = 이름·프롬프트 버전·시스템 프롬프트·출력 스키마·사용자 입력 조각들*이다. 호출마다 이것들의 해시가 **열쇠**가 된다(이미지는 파일 내용 또는 사양+렌더러 버전).

- **재생(replay)**: 녹음(`data/llm/<suite>/<변형>.jsonl`)에서 열쇠로 응답을 찾는다. 키·비용이 필요 없고 결정론이다. 녹음에 없는 호출은 `LLMMissing` — 조용히 빈 응답으로 채우지 않는다. 닫힌 고리(생성 → 심사 → 수리)는 응답이 같으면 입력도 같아서 재생만으로 그대로 재현된다.
- **실호출 기록(record)**: `HybridClient` 가 녹음에 있으면 재생하고 없으면 실제 호출해 *덧붙인다*(이어하기). 예산 상한(`Spend`: 입력 글자 수로 사전 잠금, 응답 usage 로 정산), 동시 호출은 잠금 아래에서 상한을 지킨다.
  모델·요청이 낸 실패(잘림·거절·형식 오류·스키마 400·시간 초과)는 *녹음한다* — 그것이 측정이다. **계정 오류(크레딧 소진·인증·권한)는 멈추고 기록하지 않는다**([D-17](DECISIONS.md), [F-28](FAILURES.md)).
- **dry-run**: 대역 클라이언트로 닫힌 고리를 끝까지 돌려 호출 수와 보수적 추정 비용을 낸다 — 사용자 승인의 근거다. **check**: 한 사례만 실제로 불러 요청이 받아들여지는지 본다(측정에 넣지 않는다).
- **비용 장부**(`adgate llm spend` → `artifacts/llm_spend.json`): 호출 기록에서 *실제로 쓴* 토큰·추정 비용·지연을 변형별로 모은다. 문서의 비용 수치는 여기서만 온다.
- **실패 분석**(`adgate llm analyze`): 틀린 사례의 목록과 이유를 재생으로 뽑는다(채점 수치가 아니라 *어디서* 틀렸는가).
- **GitHub Actions `llm-live`**: 키가 있는 작업은 읽기 권한뿐이고 쓰기 권한이 있는 작업에는 키가 없다. 결과는 브랜치로 올라오고, 재생·집계는 키 없이 깨끗한 작업트리에서 한 번 한다.

`suites.py` 가 이 모두를 *suite*(사례 목록 + 사례 하나를 처리하는 driver + 채점 + 선택적 오프라인 팔·실패 분석)로 일반화한다(`adgate llm list`): 모델 변형이 있는 `campaign`·`campaign_reply`·`creative`·`vision`·`insight_llm`·`judge_gray`, 모델 없이 도는 `insight`·`ops`·`ops_load`·`catalog` 와 산출물 요약용 suite.

## 4. 평가 절차 (이 저장소의 본체)

1. **사전등록** — 가설·지표·합격 기준·*예상(확률)*·판단 규칙을 측정 전에 쓰고 해시로 고정한다(`adgate prereg`). 본문은 고치지 않는다 — 결과는 뒤에 덧붙이고 틀린 예상은 '빗나감'이라 적는다.
2. **독립 데이터** — 작성자가 시스템 코드를 보지 못한 독립 에이전트(같은 모델 계열이라는 한계를 문서에 적는다). 평가셋은 해시로 동결한다.
3. **첫 접촉 한 번** — 깨끗한 작업트리에서 한 번 재고 `artifacts/history/` 에 그대로 보존한다. 수치가 마음에 들지 않아 프롬프트·스키마·탐지기를 고쳐 같은 측정을 다시 하지 않는다(다른 설정은 새 사전등록).
4. **실패 분석 → 좁은 수정** — 실패를 부류로 나눠 [FAILURES.md](FAILURES.md) 에 적고, 고친다면 *검증 가능한 구조*(문형·표기)만, 악용 사례와 정상 유사 사례를 함께 시험하며([D-12](DECISIONS.md)) 수정 뒤 수치에는 ‘수정 후, holdout 아님’을 단다.
5. **문서의 수치는 산출물에서만** — `<!-- num:경로|형식 -->` 표식을 `adgate docs` 가 `artifacts/*.json` 에서 채우고 CI 가 일치를 검사한다.
