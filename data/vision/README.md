# 이미지 광고 평가셋 (`data/vision/`)

이미지 읽기(VLM)와 그 결과가 심사 판정에 주는 효과를 재는 평가셋이다. 평가 계획은 [docs/EVAL_VISION.md](../../docs/EVAL_VISION.md).

| 파일 | 내용 |
|---|---|
| `vision.jsonl` | 소재 60건(조각 A–F × 10). 소재(이미지 속 글자 없이) + 이미지 사양(JSON) + 정답(판정·위반·태그) |
| `images/V-*.png` | 사양에서 그린 PNG 60장. 커밋한다 — 열쇠가 파일 내용이라 녹음 재생이 렌더링 환경에 흔들리지 않는다 |

전체가 동결돼 있다(`MANIFEST.sha256`, 파일 61개). 정답 이미지 속 글자 덩어리와 시각 단서는 사양에서 **기계적으로** 나오고(`src/adgate/vision/spec.py`), 심사 정답은 작성자가 정책을 읽은 결과다.
작성자 6명(조각 A–F × 10건)은 `POLICY.md`(가상의 광고 심사 정책)와 `IMAGE_SPEC.md`(사양 설명), 의뢰서, 형식 검사기만 보고 썼다. 같은 모델 계열의 별도 컨텍스트 LLM 이다. 사람이 만든 광고가 아니다. 모든 업체·상품·기관은 가상이다.

구성 태그(소재마다 정확히 하나): `image_only` 24 — 위반이 이미지 속 글자에만 · `benign_image` 18 — 위반 어휘와 비슷하지만 정책상 정상 · `visual_cue` 12 — 시각 요소(전·후 비교, 카운트다운, 가짜 경고창, 수상 배지)가 판단에 영향 · `both` 6 — 텍스트와 이미지 둘 다에 위반.

## 작성자가 멈칫한 곳 (보고에서 모음)

의뢰서·정책·사양의 공백이며 정답은 작성자의 판단이다. 고치지 않았다.

- **의뢰서 오류(설계자의 것)**: 의뢰서의 정상 유사 예에 ‘근거를 밝힌 순위’를 넣었지만 정책 ABS 는 조사 주체와 연도가 있으면 REVIEW 다. 작성자 셋(B·C·F)은 정책을 따라 REVIEW 로 쓰고 시각 단서로 분류했다 → 정상 유사의 ‘순위’ 부류가 의뢰서 의도보다 적다.
- 별점이 ENDO(‘만족도 98%’)의 검증 수치와 구분되는지 정책에 없어, 작성자 여럿이 별점 정상 유사를 피했다 → 별점 판정은 이 셋이 덮지 않는다.
- ABS 의 근거(조사 주체·연도)가 *별도 이미지 항목의 각주*(‘*’ 연결)에 있을 때 같은 각주로 보는지 정책에 없다(B09, F08, E04).
- ‘오늘만’ 같은 목록어 없이 카운트다운 타이머만 있을 때 URG 인지, URG 의 랜딩 근거(기간·수량)가 행사 기간이어야 하는지, 배송 기간 같은 무관한 기간도 되는지(C08, A10).
- LND(랜딩 대조)가 이미지 속 수치도 ‘광고의 수치’로 대조하는지(C10), 수치가 여럿일 때 기록 단위(C07).
- HLT 적용 범위: 서비스(두피관리실)와 ‘개선 + 증상(여드름)’(B). 전·후 비교(split) 자체를 위반으로 보는 규칙이 없다(B08). HLT 는 앱·교육에 적용되지 않아 그 주제로는 HLT 소재를 못 만들었다(D).
- GUA: 이미지의 ‘원금 보장형’은 고지의 ‘원금 손실이 발생할 수 있으며’가 있어도 직접 부정하지 않으므로 위반으로 썼다(F02).
- 경고 포스터가 사기 문구를 ‘예시로 인용’하는 경우: 정책 8.7 은 ‘같은 절의 요청·명령’만 다루고 FRD 에는 review 등급이 없어 REJECT/APPROVE 로만 갈린다(E05, D08, D09).
- gambling 업종에 같은 이미지의 도박 홍보 문구까지 BRD 를 따로 기록할지 불분명(E09, E10).
- FIN-01 은 `image_text` 를 합산하므로 이미지 작은 글씨의 고지도 충족으로 본다 → **읽기 모델이 작은 글씨를 놓치면 FIN-01 오탐이 생긴다**(A01·A05·A06). 숫자뿐인 카운트다운이 URG 인지, 출처 없는 인증 배지가 ENDO 인지 정책에 명시가 없다(A09, A10).
- 사양 한계: `rotate` 는 글자만 돌고 `bg` 칸은 안 돌아 자동 맞춤 글자가 칸 밖으로 삐져나왔다 → 렌더러를 고쳤다(회전한 글자의 바깥 사각형이 칸 안에 들어오게 맞춤 영역을 줄임, 렌더러 `vision-v2`). 두 열 배치의 읽는 순서는 (y, x) 정렬로 통일했다. `stars` 는 글자와 무관하게 항상 별 5개가 꽉 차게 그려지고, 팝업은 높을수록 버튼 글자 윗변이 잘리며, `badge` 는 `size` 가 없어 줄바꿈을 못 정한다.

## 독립성 기록

- 렌더러는 작성자 E 의 보고로 한 번 고쳤다(`vision-v2`). 고친 뒤 이미지는 모두 다시 그렸다.
- 설계자는 렌더러 점검과 형식 검사를 위해 사양과 그려진 이미지를 볼 수 있었다. 읽기 모델과 심사 엔진의 이 셋 위 결과는 첫 접촉 전에 보지 않았다.
